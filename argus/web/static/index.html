HOW IT WORKS

A resolution cascade that stops at the first success

Each step runs the tiers in order and only T3–T5 spend tokens. Bar widths are the real share of steps from the latest aggregate.

 

Step contracts

Every step carries a falsifiable contract captured from the green run: the API calls it makes, where it navigates, which screen appears. A mismatch becomes evidence with no model involved.

Immutable intent vs per-build plans

A test’s intent is frozen the first time it is saved and can never be rewritten by healing. The runtime mutates only the compiled plan, versioned per build, so evidence is always compared against a trusted baseline.

Verified-only memory

Whatever Argus learns is written to git-friendly JSON — but nothing is learned from a failed run. The same situation costs $0 next time.

BUG OR FEATURE?

Two real verdicts, side by side

Pulled from a recorded run. An intended change is accepted only with a verbatim release-note citation; without one, a change is never silently accepted.

 
 

Ambiguous cases go to a jury of models; a change is split to NEEDS_REVIEW rather than guessed. When there is no changelog at all, argus diff runs the same immutable intents against two live builds and compares behaviour traces.

THE 10TH RUN

Steady state costs nothing

Ten replays across releases 1.0 → 1.2 with the LLM off. Bars are LLM calls; the line is the share of steps replayed at T0.
