Autonomous UI testing · FlytBase "The Tireless Hand"

Argus Live tests the cockpit like an operator — and checks every claim against the drone's real state.

A page can show a drone online while it is offline, keep a frozen video labelled “live”, or lose an operator's action after a reconnect. Argus drives the real product in a real browser, injects changing conditions, and decides bug‑vs‑noise by comparing what the screen says with the simulator's ground truth — so it finds real issues with almost no false positives.

The core idea

Don't ask a model “does this look right?”. Ask the source of truth.

Vision‑only testers guess, and guesses produce false positives. Argus does the opposite: it reads what the operator sees (labels, telemetry, the video element, map markers) and compares it against what the system actually knows.

Every product in this challenge sits on the same simulator and control API, so Argus can always obtain independent truth: the true drone status and position, the backend's health, the active faults, and a socket feed subscribed exactly like the cockpit. When the two disagree in a way that harms the user, that's a bug — proven, not guessed.

The clever bits

Five techniques that make it precise

01 · truth oracle

UI vs simulator, not vision

Bugs are decided by comparing the screen with the control API and socket feed. No model opinion in the verdict path → near‑zero false positives.

02 · map

Reads Cesium by walking the React fiber

To check a marker's position, Argus finds the live Cesium viewer through the page's React fiber and reads each entity's real lat/lon and screen box — exact, no screenshot guessing.

03 · video

Frame counters + perceptual hash

Liveness comes from the <video> element's decoded‑frame count and a 16×9 luminance hash — so a frozen stream still labelled “live”, or a label that switched while the picture didn't, is caught.

04 · evidence

The recording narrates itself

A HUD overlay is burned into every video showing the step, the UI's claim, the ground truth and the verdict — the video is the reproducible evidence, produced automatically.

05 · precision

Group symptoms, guard against noise

One fault's many symptoms merge into a single issue. Guards prevent false alarms — e.g. a control is scrolled into its own container before it can be called “unreachable”.

06 · reuse

Built on the Argus semantic engine

The same self‑healing element matching used across the project reads the UI by meaning (role, accessible name, context), so small markup changes don't break the probes.

How you run it

A real CLI

# run one scenario live (a real Chrome opens)
argus live run --only S2

# run the full suite, record every scenario
argus live run

# generate the submission document from the runs
argus live report

Each run writes runs/live/<id>/ — an MP4, screenshots, timed samples and a machine‑readable result.json — then rolls them into EVALUATION.md.

The broader Argus CLI (used elsewhere in the project) also ships:

argus run        replay + self-heal + triage
argus explore    crawl an app into a map
argus generate   write a suite (1 LLM call)
argus diff       two builds, no changelog
argus gauntlet   mutation benchmark
argus doctor     preflight checks
Inside a coding agent

MCP — close the software‑factory loop

Argus is also an MCP server, so a coding agent (Claude Code, Cursor, opencode…) can test its own work in a real browser before opening a PR.

# register once
claude mcp add argus -- argus mcp

The agent writes a feature, then calls verify_change("what I intended"). Argus runs the browser suite and answers BUG with repro steps or INTENDED CHANGE with the release‑note citation — the intent it was given is the oracle.
